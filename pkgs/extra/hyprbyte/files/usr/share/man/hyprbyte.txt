hyprbyte - a tiling window manager for ByteOS

Hyprbyte puts terminals side by side, like Hyprland on Arch. Each window
runs its own ByteShell (or one program); new windows split the space
(dwindle) and there are nine workspaces. Like Hyprland it draws no bar
itself: install quickshell and add  exec-once = quickshell  for one.

START
  start-hyprbyte                from the shell; Mod+Shift+E returns to it
  Hyprbyte is not a login session: log in to ByteShell, then start it.
  start-hyprbyte --no-animations  passes options on (hyprbyte works too)

KEYS (Mod = Alt unless the config says otherwise)
  Mod+Enter          a new terminal
  Mod+D              run a program (rofi when installed, else a small box)
  Mod+W              switch to any window (needs rofi)
  Mod+L              lock the screen (needs hyprlock)
  Mod+Q              close the window in focus
  Mod+Arrows, Tab    focus the previous / next window; a click focuses too
  Mod+Shift+Arrows   move the window back / forward in the layout
  Mod+F              full screen
  Mod+1 ... 9        workspace 1 to 9
  Mod+Shift+1 ... 9  send the window there
  Mod+Shift+E        quit (every window is closed)

  Everything else goes to the window in focus, Ctrl+C included.

SETTINGS
  /etc/hyprbyte.conf, then ~/.config/hyprbyte.conf:
    mod = alt | super | ctrl
    gaps_in = 1          gaps_out = 1
    animations = yes     rounding = yes
    open = btop          a window at the start (any number of them)
    exec-once = quickshell   a program in the background, no window
    bind = MOD SHIFT, R, spawn, rofi -show run
          mods (MOD, SHIFT, CTRL), a key (A-Z, 0-9, RETURN, SPACE, TAB,
          LEFT, F1 ...), a dispatcher (see hyprctl) and what it gets;
          the same keys again replace a built-in binding

THE ECOSYSTEM (packages, each started with exec-once or a key)
  quickshell   your own bars         dunst       notification pop-ups
  rofi         launcher, windows     hyprlock    lock screen
  hypridle     act on idle time      hyprpaper   wallpapers

LAYERS
  Other programs draw through the state Hyprbyte shares:

    local hypr = package.loaded["hyprbyte.state"]   -- nil: not running
    local layer = hypr.addLayer({ namespace = "mybar", anchor = "bottom",
      height = 1,
      draw = function(gpu, x, y, w, h) gpu.set(x, y, "hello") end,
      click = function(x, y, button) end })
    hypr.removeLayer(layer)

  anchor   "top" / "bottom": a panel (a bar); its rows stay free of windows
           "overlay": above the windows, where place(SW, SH) returns
           x, y, w, h (default: everything); windows never draw over
           it. exclusive = true hides the windows, panels and the other
           overlays meanwhile (a lock screen)
           "background": below the windows (a wallpaper)
  hypr.grab(layer) sends every key to layer.key(event, card, char, code)
  until hypr.ungrab(layer) or removeLayer; hypr.refresh() draws again.

  Panels and overlays are drawn every second and when focus, workspaces
  or titles change. hypr.workspaces, hypr.active, hypr.focused(),
  hypr.lastInput (uptime of the last key or click) and hypr.dispatchers
  (as for hyprctl dispatch) tell and do the rest. A layer goes away with
  the program that added it.

HYPRCTL
  hyprctl clients | workspaces | activewindow | layers | version
  hyprctl dispatch exec btop
  hyprctl dispatch workspace 2 | movetoworkspace 3 | killactive
  hyprctl dispatch spawn rofi | focuswindow 3
  hyprctl dispatch fullscreen | cyclenext | cycleprev | exit

MEMORY
  Each window is a shell and a screen buffer; on a Tier 2 screen two or
  three windows are comfortable, with Tier 3 memory more.
